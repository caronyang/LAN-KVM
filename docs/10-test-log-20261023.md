## 回切修正（2026-10-23 晚）

### 問題

A 控制 B 時，把游標推回 B 左邊界不會回 A。原因：client 要累積 `dx <= -30` 才送 Release，使用者把游標停在邊界就停了，永遠差 30px。

### 修正

client 改為「游標回到進入邊界、再外向 2px」立即送 Release：

```rust
let exit = (entry_edge == 1 && virtual_x < -2)
    || (entry_edge == 2 && virtual_x > 2);
```

- 不再需要多推 30px。
- 非控制狀態下的 Motion/Button/Key/Wheel 直接忽略，避免回切後殘留封包繼續移動 B 的游標。
- B 的本地鍵鼠**不改變狀態**（不做 local takeover）。
- 版面左右由 master 的 `--edge right|left` 設定；UI 之後用佈局畫布設定（`docs/02` 4.5）。

### 驗證

本機以假 master 送 `Switch` → `Motion +100` → `Motion -101`：

```
[client] controlled; entry at (0, 494) from left
[client] released at edge
```

## 只能切換一輪（2026-10-23 修正）

### 現象

第一次 A→B、B→A 都成功；第二次 A→B 完全沒反應，但 A 的 `poc` 仍在跑。

### 根因

`EdgeDetector` 觸發後會把 `fired` 設為 `true`，必須 `reset()` 才能再觸發。`do_switch` 有設，但 `do_release` 沒有重設，所以回切後偵測器永久失效。

### 修正

`do_release` 在解除 ClipCursor／恢復游標後重設偵測器：

```rust
if let Some(detector) = EDGE.get() {
    detector.lock().unwrap_or_else(|e| e.into_inner()).reset();
}
```

### 可設定的門檻

| 設定 | 位置 | 預設 | 說明 |
|------|------|------|------|
| `--trigger-px` | master CLI | 20 | 邊界要外推多少 px 才切換 |
| `--trigger-ms` | master CLI | 300 | 累積push的時間窗 |
| `--release-px` | client CLI | 2 | 回切要越過進入邊界多少 px |
| `release_px` | `C:\ProgramData\LAN-KVM\config.txt` | 2 | service client 的回切門檻 |

範例：

```powershell
# A：比較靈敏（12px 就切）
.\lankvm-devtools.exe poc --role master --peer 192.168.68.68 --port 45871 `
  --edge right --trigger-px 12 --trigger-ms 300 --seconds 600

# B：回切只要越界 1px
.\install-service.ps1 -ClientPort 45871 -ReleasePx 1
```

> `release_px` 存在 `config.txt`；`install-service.ps1` 會一併寫入。改完要 `lankvm-service.exe stop/start`。
